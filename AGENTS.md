## User communication preferences

- Use a visual HTML artifact for planning, brainstorming, and design discussions.
- Always include diagrams in these artifacts. Put each diagram beside its explanation.
- Present one idea at a time in short tabs or steps. Use simple explanations and diagrams. Put technical details behind optional expansion controls.
- Do not copy long Markdown documents into a continuous HTML page. Keep the HTML digestible and link to Markdown for the full record.
- Write artifact text and planning responses in ASD-STE100 Simplified Technical English: short sentences, active voice, consistent terms, and no idioms. Keep sentences to 20 words or fewer.
- Do not use terminal output as the explanation. Open the artifact in a browser when permitted. Provide a direct artifact link.
- Keep concept and planning HTML artifacts in `.local-artifacts/`, which Git ignores. Maintain them separately from repository documentation.
- Write durable repository documentation in Markdown. Include Mermaid diagrams where useful. Do not link repository docs to ignored local HTML files.
