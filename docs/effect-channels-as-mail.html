Keep these three jobs separate.

The room supplies tools.

A place to send messages. Saved notes. A way to wake up later.

Channels follows message rules.

Spot repeats. Hold waiting messages. Retry unfinished steps. Send saved answers.

Your robot does the task.

Read the notes. Solve the problem. Decide what answer to give.

You could write the helper yourself. Channels saves you from rebuilding its message-handling rules.

If the robot stops halfway, its own program must know how to continue. The notebook cannot do that thinking.

Trying again can also repeat an action. Channels reduces mistakes; it does not make every reply happen exactly once.

Only if you want the real names
  • Reactive programming: write code that responds when something arrives or changes.
  • Akka: build software helpers that send each other messages. You still choose their rules and saved memory.
  • Durable Object: Cloudflare supplies the room, saved notebook, and alarm. Your code chooses what to put in them.
  • Channels: ready-made rules for handling conversation messages. It can use Durable Objects or other storage.
  • Agent: the robot program that performs your task.

These names describe different jobs. They are not four names for the same thing.

A small accuracy note

The room is a picture, not a computer that runs forever. Cloudflare can stop and restart its code.

Saved notebook entries remain after a restart. Ordinary notes kept only in the program’s memory do not.

Akka handles one message at a time, but a task can continue after that message handler finishes.

A Durable Object can also handle another request while it waits for outside work.

That is why Channels keeps an explicit record of which conversation work is still active.
